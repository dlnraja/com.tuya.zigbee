## 🔴 CRITICAL: Peter OOM Memory Crash (#2183, #2166)

### Diagnosis
Peter's Homey screenshot shows **Universal Tuya using 93.8 MB RSS** (Homey hard limit ~64MB per app).
This causes OOM, flow failures, and device non-responsiveness.

### Root Causes Identified
1. **AutonomousEnricher**: loaded entire `mfs_db.json` (6.87MB) into `this.liveMappings` on startup.
   Combined with fetching Blakadder JSON after 1 hour → double memory load.
2. **LiveDataUpdater**: heap guard used `heapUsed` (V8 heap only) not `rss` (what Homey counts).
   Guard threshold (48MB heapUsed) was too optimistic vs. true RSS footprint.

### Fixes Applied
- `lib/dynamic/AutonomousEnricher.js`: Deferred startup `loadLocalMappings()` (P183 RSS guard).
  mfs_db data already available via DeviceFingerprintDB — no duplicate load needed.
  Remote fetch now starts at 2h (was 1h) to stagger from LiveDataUpdater.
  Added `_rssTooHigh()` RSS+heap check before fetch.
- `lib/dynamic/LiveDataUpdater.js`: `_heapTooHigh()` now checks RSS > 55MB OR heapUsed > 40MB.

- Contact sensors ("Raam"): paired but show lux values (1375/2156/1423 lx) instead of open/close

### Contact Sensor lux phantom issue
`contact_sensor` driver compose has `measure_luminance` capability. Some mfrs in this driver
are pure contact-only (IAS Zone). When the SelfHealingDevice auto-injection fires on a phantom DP,
lux gets added to contact sensors that have no lux hardware. 

**Action needed**: Audit which mfrs in `contact_sensor` actually have illuminance DP, and split or
gate `measure_luminance` behind a settings-driven opt-in.

### Gabriel's UX Feedback: Sub-Device Tiles (post #2178, #2182)
Gabriel reports that multi-gang switches should show as **separate sub-device tiles** (one per gang)
rather than bundling all gangs into one device. Key reasons:
1. Individual names per gang (Homey can't rename capability instances)
2. Quick actions (one-tap, widget, voice) only work on main capability
3. Google Home / Alexa voice control fails for per-instance caps

**Gabriel's implementation**: persistent backlight (survives power cut), per-gang power-on behavior,
flow trigger on reconnect-after-power-cut, retry on failed commands (350ms × 3), jitter on reporting
interval (±10%), message count stats, multilingual.

**Recommendation (MASTER_ONLY)**: Implement Zigbee sub-device splitting per gang for TB25 class drivers.
This requires `isSubDevice()` pattern from ZigBeeDevice SDK.
