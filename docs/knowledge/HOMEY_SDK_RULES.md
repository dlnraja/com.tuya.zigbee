## Levels

Athom validates at three cumulative levels (`homey app validate --level debug|publish|verified`):

| Level | Meaning | Our CI |
|---|---|---|
| debug | Checked on every build/run | blocking |
| publish | Additionally checked by `homey app publish` and Athom processing | blocking |
| verified | Only for Verified Developers | report-only (we are not verified) |
| project | Lessons from our own Athom history or hygiene, not an Athom rule | blocking only when it caused a real refusal, report-only otherwise |

## Where it runs

- `node tools/ci/homey-sdk-rules.js`: uses `.homeybuild/app.json` when present (build mode), otherwise the root `app.json` plus every driver's `driver.flow.compose.json` (compose mode).
- pre-commit (`.githooks/pre-commit`): compose mode, blocking rules only.
- `pr-gate.yml`: compose mode, blocking, plus a JSON report artifact.
- `homey-sdk-rules-refresh.yml`: weekly diff of node-homey-lib facts, the homey CLI and the SDK docs; opens a draft PR (paths are `[skip ci]`-safe).
- Kill switch: `HOMEY_SDK_RULES_DISABLED=1`. Report-only run: `--report-only`.
