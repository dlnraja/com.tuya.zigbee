## What is added
- `TuyaProtocolVersions.js`: 3.1/3.2/3.3/3.4/3.5 documented; `3.22` = 3.3 + device22; `1.x`/`2.x` = cloud/firmware labels (pv/bv), not LAN, so the documented chain is probed; unknown `3.x` (e.g. 3.6) = lead, probes documented versions only. Chain = declared → neighbours → probe order. Frame detection: 0x6699 → 3.5, 0x55AA + ASCII tag → 3.x. Wired into `buildProtocolFallbackChain`.
- `TuyaCommandPlan.js`: CONTROL(7) vs CONTROL_NEW(13), DP_QUERY(10)/DP_QUERY_NEW(16)/device22, bounded UPDATEDPS(18) payload, cid wrapping for gateway sub-devices.
- `TinyTuyaImport.js`: tinytuya wizard import, gateway children inherit the gateway key/ip.
- `LocalConnectionGate.js`: one LAN session per device id (wired into `TuyaLocalClient.connect/destroy`).
- `TuyaLocalClient`: live queue capped at 64, "socket hang up"/ECONNABORTED/ETIMEDOUT now retried (max 2).
- `WiFiDPRegistry`: tuya-local schemas (1 908 exact product ids, 1 463 schemas, 21 capabilities), lazy read, only the rows looked up are cached (max 64); `GenericDpAutoMapper` (high confidence only, opt-in via `observedDps`).
- `lib/tuya/TuyaZigbeeProtocolProfile.js`: EF00 commands (0x01/02/03/04/05/06/0B/10/11/12/24/25), DP types, appVersion decoding, mfr-prefix generations (_TZ3000/_TZ3210/_TZ3290/_TYZB01 ZCL; _TZE200/_TZE204/_TZE284/_TZE600/_TYST11 EF00), profile 0x0104 (3.0 vs HA 1.2 decided by zclVersion), DP frame parser chain standard → short_len → lead. Native stays first in every chain.

## Remaining
- Zigbee profile and generic mapper are not wired into the device runtime yet (pure modules + tests).
- Enum-backed tuya-local binary sensors skipped (need a value table).
- MCU serial and BLE versions are documented only (not a LAN or Zigbee path for us).
