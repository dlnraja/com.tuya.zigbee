# Tuya parsing helpers and lib/utils helpers (hand-written reference)

Written 2026-11-23 for the documentation coverage work (P3399), continuing [MODULES_TUYA_LOCAL_AND_TUYA_HELPERS](MODULES_TUYA_LOCAL_AND_TUYA_HELPERS.md). Each entry says in our own words what the module is for, its main exports, how it is guarded and where it is wired. "Importers" counts the other files under `lib/`, `drivers/` and `app.js` that `require()` it on master at the time of writing; 0 means nothing in the app loads it today (kept for reference, never removed without a check). Modules reached only through a folder `index.js` count that index as an importer.

## Tuya parsing and DP helpers (`lib/tuya/`)

- `lib/tuya/TuyaUnifiedParser.js` (v5.5.142) - the large shared parser (about 1,270 lines). Holds the Tuya DP type and command constants, per-fingerprint `DEVICE_PROFILES` (about 60 manufacturer names), per-driver-type DP and ZCL tables, and `UNIVERSAL_DP_PATTERNS` used as the last fallback. `getContextualDpMapping(dp, mfr, pid, driverType)` resolves in that order: device profile (with `inherit`), driver type, universal pattern. `parseTuyaFrame` tries several frame layouts (offsets) and keeps the first that yields DPs; `tryParseDPs` stops on DP id 0 or above 200, unknown types or a length that overruns the buffer. Also exposes IAS zone/ACE hints, generic ZCL listener setup and builders for time-sync, data-query and MCU-version frames. Importers: 4 (`lib/tuya/index.js`, `UnifiedPlugBase`, `UnifiedSensorBase`, `UnifiedLightBase`).
- `lib/tuya/TuyaUnsignedValue.js` (P2580) - some stacks surface a Tuya VALUE (type 2) as a signed int32, so a distance of 2.2 m could show as millions below zero. `asUnsignedTuyaValue` turns a number, BigInt, Buffer or wrapped object into an unsigned 32-bit integer (null when not numeric); `toTuyaScaledUint` encodes a human value times a divisor for sending, never negative and clamped to optional min/max; `counterSafeRaw` restores `meter_*` counters that wrapped below zero (other capabilities untouched). Importers: 5 (`TuyaRadarRangeScale`, `UnifiedSwitchBase`, `UnifiedPlugBase`, `TuyaUnifiedDevice`, ...).
- `lib/tuya/UpstreamDpGuards.js` (P3150) - two small facts confirmed upstream (ZHA quirks PRs, credited in the file; no code copied): `isUnsetFadingTime` ignores DP12 values outside 3-600 s for the exact couple `_TZE204_1youk3hj` (an unconfigured radar reports 0xFFFFFF08), and `zm25elDirectionDp` gives the DP5 enum (0 forward, 1 back) for two Zemismart ZM25EL manufacturer names, null for any other. Importers: 2 (`presence_sensor_radar`, `curtain_motor`).
- `lib/tuya/dpMapper.js` (v5.3.17) - one function, `mapTuyaDPToCapabilities(device, dp, value)`: a switch over the common DP ids (1-5, 7-10, 14, 15, 18, 19, 33, 35, 101-104, 247) that writes the matching capability only when the device already has it. Returns silently without a device. Importers: 1 (`BaseTuyaDPDevice`).
- `lib/tuya/fingerprintShardId.js` (P2678) - gives the shard file name for a manufacturer name so the runtime never parses the whole fingerprint catalogue (about 0.9 MB) on a 64 MB Homey. Known prefixes (`TZE200`, `TZ3000`, `HOBEIAN`, ...) become the shard; the five largest families are split again by the first character of the suffix; anything else goes to `OTHER_<letter>`. Shared by the runtime and the shard builder in `tools/ci`. Importers: 1 (`DeviceFingerprintDB`).
- `lib/tuya/profiles/P3013DedicatedZ2MProfiles.js` (P3013) - exact DP tables, rewritten from Zigbee2MQTT definitions (contributors credited in the file), for four dedicated master drivers: the AE-5503 sauna thermostat, the Moes MG-BJQ002 siren with night light, a 6-gang metering panel and the Novato ZPV-01 valve. Needed because the shared bases read the same DP ids differently. Exports the frozen profiles, `rxTable` (a mutable copy for the bases), `truthy`, and `sendEncoded`, which tries the shared EF00 max-fallback sender first and then the device's own `_sendTuyaDP`. Importers: 4 (the four drivers).
- `lib/tuya/tuyaDpBool.js` - reads a boolean DP from any shape seen in practice: a wrapped event (`value`/`data`), `true`/`1`, strings such as "on", "open", "false", a one-byte Buffer, or the `hex:01` form found in diagnostic logs. Returns null when unsure instead of guessing. Exports `tuyaDpBool`, `tuyaDpPayload`, `fromHexTag`. Importers: 1 (`PhysicalButtonMixin`).

## Button, gang and frame helpers (`lib/utils/`)

- `lib/utils/ButtonE000RawInterceptor.js` (P2387) - the single place that hooks raw 0xE000 frames on button remotes. It always chains through `wrapHandleFrame` (append-only), because drivers that replaced `handleFrame` used to cut off the physical-button chain (P2328). By default it reads button number and press type from the payload (button index only trusted when within `maxButton`) and calls `triggerButtonPress`; a custom `onFrame` hook can replace that. Errors are logged and the next handler always runs. Returns false when the node has no `handleFrame`. Importers: 8 (`WallSceneRemoteHybridInit`, `button_wireless_scene`, `remote_button_wireless_smart`, ...).
- `lib/utils/GangIndexResolver.js` (P92.121) - some firmwares number buttons or scenes from 0, others from 1. `resolveGang` learns this per device and per source: the first time an index 0 is seen the source is stored as 0-based in the device store and later indexes are shifted by one. The result is always a gang number of at least 1, clamped to the known gang count (logged). `resolveDpGang` is the DP variant. Importers: 1 (`PhysicalButtonMixin`).
- `lib/utils/TuyaDatapointArgs.js` (P2866) - `normalizeDatapointArgs` fills what a bare `datapoint` command left out: status 0, a rolling transaction id, and the length of the payload (an array payload becomes a Buffer). Without it the frame went out with length 0 and the device ignored it (issue #560 root cause). Fully specified calls pass through unchanged. Importers: 1 (`TuyaSpecificCluster`).
- `lib/utils/dp-transform.js` (P3065) - `applyTransform(t, v)` applies either a plain function or a converter object with `fromDevice`; a throwing converter object falls back to the input value. Importers: 1 (`UnifiedSensorBase`).

## Logging and memory guards

- `lib/utils/boundedJson.js` (P3068) - `boundedJson(value, max = 240)` for log lines in frame and DP handlers: never throws (cycles, BigInt), prints Buffers as short hex (first 32 bytes) and caps the length, so a DP flood does not fill the heap through the log ring buffer. Importers: 14 (`TuyaDeviceMixin`, `TuyaEF00Parser`, `TuyaUnifiedParser`, `TuyaClusterWrapper`, ...).
- `lib/utils/dp-log-sampler.js` (P3065) - decides how much of each received DP is logged: everything when developer debug mode is on; otherwise the first frames of each DP, every value change and every 50th repeat, with the raw payload cut at 96 characters. Counters in the diagnostic stats stay exact. Exports `shouldLogDp`, `shouldLogDup`, `shouldLogSampled`, `shouldLogChange`, `compact`, `formatRaw`, `frameSig`, `isVerbose`. Importers: 5 (`TuyaDataQuery`, `TuyaEF00Manager`, `AutoAdaptiveDevice`, `BaseUnifiedDevice`, ...).
- `lib/utils/MeterWriteCoalescer.js` (P3298) - for chatty metering devices (power clamp diagnostics showed the same value written several times per frame). An identical value within `refreshMs` (5 min) is skipped; distinct values closer than `minIntervalMs` (2 s) are merged and the latest is written once the interval passes; `latest(cap)` gives the newest accepted value so derived totals never read a stale one. Never throws (errors go to `onError`); `flushAll`/`destroy` for teardown. Also exports `KeyedLogThrottle` (one line per key per window, bounded key count). Importers: 1 (`power_clamp_meter`).

## Device lifecycle and base-class safety

- `lib/utils/ClassExtendsGuard.js` (P24.7, P64.0) - `safeExtends(name, loader)` so `class X extends ...` never receives undefined when a parent fails to load (circular import, missing module). It accepts a default export or a named export, then falls back to `ZigBeeDevice` through several loaders, then to a minimal no-op device class, logging which fallback was used. Importers: 4 (`SDK3CompatBridge`, `wall_dimmer_1gang_1way`, `smart_scene_panel`, `smart_knob_rotary`).
- `lib/utils/ManufacturerNameAccessor.js` (P59) - adds `getManufacturerName()` to the `ZigBeeDevice` prototype at app start, after forum reports of "this.getManufacturerName is not a function" crashes on radar sensors (topic 140352). The getter never throws and may return an empty string; `withManufacturerName` runs a callback with it safely. Importers: 1 (`app.js`).
- `lib/utils/SafeTimerAccessor.js` (P62) - adds `safeSetTimeout`, `safeClearTimeout`, `safeSetInterval`, `safeClearInterval` and `isDestroyedSafe` to the `ZigBeeDevice` prototype at app start, after diagnostics full of "reading 'setTimeout'" errors once `this.homey` was gone (device deleted or early init). Backed by `safe-timers.js`; none of them throws. Importers: 1 (`app.js`).
- `lib/utils/LifecycleCleanup.js` - shared teardown helpers for the base classes: `safeCleanupManager` (calls `cleanup` or `destroy`), `removeClusterListeners`, `clearTimers`, `clearIntervals`, `performFullCleanup`, and `safeReadAttribute` with a timeout. Each step is wrapped so one failure never stops the rest. Importers: 1 (`BaseUnifiedDevice`).
- `lib/utils/TitleSanitizer.js` - cleans device names after pairing ("(Hybrid)", "[Battery]", leftover brackets) after a user report in a diagnostic. `sanitize`, `needsSanitization`, `generateDefaultName(driverId)` and `autoSanitizeDeviceName(device)`, called from `onAdded` inside a try/catch so a rename failure never blocks pairing. Importers: 2 (`BaseUnifiedDevice`, `lib/utils/index.js`).
- `lib/utils/HomeyCapabilityUx.js` (P2500, P2553, P3362) - keeps sensor capabilities (`measure_`, `meter_`, `alarm_`) getable so Homey shows tiles and History, with Insights on except for known floods (mmWave distance and classification, `alarm_motion` when `alarm_human` exists). `healSensorCapabilityGetable(device)` applies this at init and restores standard units when missing; `button.*` may stay non-getable. Importers: 2 (`TuyaZigbeeDevice`, `ButtonDevice`).
- `lib/utils/ProtocolQuirkLookup.js` (P116) - case-insensitive lookup in `data/protocol_quirk_table.json`, keyed by manufacturer name (product id optional): `getMfrQuirk`, `resolveDeviceMfr`, `getBatteryDpPlan` (splits the battery DPs into percent, voltage and alarm lists), `getInitSequence`, `reload`. A missing or broken table gives an empty table, never an exception. Importers: 2 (`PhysicalButtonMixin`, `SmartBatteryManager`).
- `lib/utils/driver-preference.js` - remembers a driver chosen by hand for a device (key `user_preferred_driver_v1`) so automatic adaptation does not override it; written after a USB double socket kept landing on the wrong driver. Every call is wrapped and returns null or nothing on error, and it refuses to load the Homey CLI binary. Note: it reads `ManagerSettings` from `require('homey')`, which SDK3 apps do not normally expose, so on current Homey it most likely always falls back to "no preference" (open lead, to verify before relying on it). Importers: 3 (`SmartDriverAdaptation`, `driver-switcher`, `safe-auto-migrate`).

## Small helpers and reference modules (some not loaded by the app)

- `lib/utils/MathUtils.js` - `safeDivide` (0 on division by zero), `safeMultiply`, `safeParse` (fallback on NaN), `safeAdd`, `safeSubtract`; split out of an older utility file to break a circular import. Importers: 1 (`Z2MConverterAdapter`).
- `lib/utils/PromiseUtils.js` - `safeAwait` (awaits only real promises, logs and returns undefined on error) and `safeCatch`, against "reading 'catch' of undefined" when a call returns a plain value. Reached through `lib/utils/index.js` only. Importers: 1 (`lib/utils/index.js`).
- `lib/utils/ClusterDPDatabase.js` - static reference tables of Zigbee clusters, common Tuya DPs and their capabilities, with `getCapabilitiesFromClusters`, `getCapabilityFromDP`, `getDPsForDeviceType` and `detectDeviceType`. Reached through `lib/utils/index.js` only; no direct caller found. Importers: 1 (`lib/utils/index.js`).
- `lib/utils/AdaptiveEventEmitter.js` (v5.3.62) - an EventEmitter that normalises data before emitting (`emitParsed`, `emitDP`, `emitZCL`), with per-event cooldowns, throttled emits, `safeOn`/`safeOnce` and bounded maps (P3068). Importers: 0.
- `lib/utils/CacheManager.js` - HTTP cache keyed by source id: sends ETag / Last-Modified, stores a SHA-256 of the body and returns stale cached data when the server errors or the network fails. Used by the source aggregator script `scripts/automation/mfs-aggregator.js`, not by the app. Importers: 0.
- `lib/utils/CapabilityAutoAdapter.js` - tracks when each capability last received data and lists unused, stale or "phantom" capabilities and observed ranges per device; nothing is removed by it. Importers: 0.
- `lib/utils/DriverUtils.js` - build-time helpers (file system based): removing brand words from labels, multi-gang checks, driver name parsing, compose file read/write, manufacturer id checks, flow card id helpers, cache cleanup and file backup. Not meant for the device runtime. Importers: 0.
- `lib/utils/RejoinDetector.js` (v9.0.40) - detects a power-restore rejoin when 3 or more DPs arrive within 600 ms, with a 30 s cooldown and a 2 s guard after our own commands so a flow switching several gangs is not mistaken for a rejoin. Idea from gpmachado's homesuite app (credited in the file). Importers: 0.
